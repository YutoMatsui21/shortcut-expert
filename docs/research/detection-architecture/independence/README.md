# 操作の独立検出可能性

**目的**：各操作の検出器をできるだけ独立させ、後段で正しい結果を統合できるか検討する。特に、専用の複合操作Handlerや中央の競合Policyを削減できるか判断するための調査。

| [現行8操作の検出方法](current-detection-methods.md) | **先に読む**：入力・開始状態・終了状態・制約をコードに沿って整理 |
| [現状の独立性・依存関係](findings.md) | 初回8操作ごとの静的調査、実装間の依存、独立化の見込み、未検証事項 |

## 判断する順序

1. **単独成立**：その操作の入力・結果・除外条件を、別操作の検出結果なしで確認できるか。
2. **実装上の独立**：他のHandlerの内部状態・メソッド・取消に依存していないか。
3. **依存の解消**：共通の観測イベント/ジェスチャ識別を使えば他Handlerなしで検出できるか。
4. **不干渉の実証**：対象Handlerだけ、他Handlerだけ、同時に動かすケースを同じイベント列で比較する。特に複合操作・除外条件・遅延確定を検証する。

**重要**：検出器を独立にしても「何でも同時に記録する」とは限らない。タスクバーのW12とW01の排他、中間の復元/配置の除外、複合ドラッグの証拠の全体整合など、製品要件上の関係は維持する。

## この調査の状態

- [findings.md](findings.md)は**実装コードと既存の操作仕様の静的調査**。検出器の独立化を実装・実測したものではなく、「独立できた」と確定した文書でもない。
- **現行構成**：[current.md](../current.md)
- **現在採用されている目標構成**：[target.md](../target.md)。独立検出＋Aggregatorは**比較検討中の代替案**であり、現時点ではtarget.mdを変更しない。
- 製品要件は[製品要件](../../../ui-requirements.md)と[操作別設計](../../../operations/README.md)を優先する。調査による設計変更は、静的レビューと検証を経てから正式文書へ反映する。
