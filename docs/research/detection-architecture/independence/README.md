# 操作検出の独立性調査

**目的**：初回対象8操作を、他の操作の検出結果や専用の複合検出器に依存せず検出し、**最後に同じジェスチャの結果を統合する**方式が成立するか検証する。

このフォルダは**調査中の仮説・確認結果・次の検証項目**を置く場所。リファクタリングの採用済み設計は現時点では[目標アーキテクチャ](../target.md)が正本であり、**本調査だけでArbitrationPolicyやInactiveCaptionHandlerを廃止したことにはしない**。

## 何を検証するか

1. **操作単独の成立条件**：W01/W02/W03/W04/W06/W07/W11/W12それぞれが、他操作の「成立結果」を読まずに判定できるか。
2. **現在の依存関係**：ほかのHandlerの状態、候補の取消、入力/状態キャッシュ、複合候補の分岐に依存する箇所はどこか。
3. **依存の解消可能性**：共通の入力・窓状態・ジェスチャ識別を渡せば、個別の操作判定を切り離せるか。
4. **不干渉の実証**：単独実行、複数Handler同時実行、結果の統合を同じ入力列で比較し、誤採用・重複・見逃しが起きないか。

## 現在の調査結果

[操作別の独立性・依存関係・未検証事項](findings.md)

**暫定結論**：8操作について、**他のW IDが採用済みであること自体を成立条件として要求する設計上の必要性は確認されていない**。一方、現在のNative実装は入力状態や競合・取消を共有し、複合操作は専用経路で検出するため、**「いま独立している」「専用複合処理をすぐ削除できる」ことは未証明**。

## 調査の記録ルール

- **事実**：コード・既存テストへのリンクとrevisionを明記。
- **推定**：独立化できそうか、何が障害かを「仮説」として区別。
- **実証済み**：実際に同じ入力を用いた単独/併走/統合テストを実行した場合だけ記載。自動fixtureのPASSとWindows実入力での成功は分ける。
- **設計の更新**：独立化の実証結果を踏まえて[目標アーキテクチャ](../target.md)と[移行計画](../migration.md)を更新する。調査中の仮説をCodexの実装仕様として扱わない。

製品上の操作条件は[製品要件](../../../ui-requirements.md)と[操作別設計](../../../operations/README.md)を優先する。
