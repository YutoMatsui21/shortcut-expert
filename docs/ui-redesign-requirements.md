## 2. 画面と操作の対象（U01・U02）

- UIは**「ショートカット一覧」「記録」の2画面**。一覧はFigmaどおり4グループ。グループは展開・折り畳み可能。
- 一覧と記録画面は、下記の**同じ14操作をすべて**扱う。Figmaの記録11行は表示例であり、3操作を機能上除外しない。
- 14操作について、**マウス・ショートカットキーの両方の検出と記録、条件が成立したときの学習通知を最終目標**とする。Figmaへの表示だけで「検出対応済み」と判定しない。
- マウス操作と提示キーの**同等性を確認できない場合は、誤った通知を出さずに記録のみ**行う。この状態は完全対応として扱わない。対応条件・制約をユーザーから隠さない。
- 現行コードには操作ID 11件、条件付き検出実装5件がある。既存IDとの対応・追加ID・衝突・状態依存の同等キーは技術調査で明確化する。検出不可能な操作が判明したら、仕様を勝手に削除・改名せず相談する。

## 3. UI・表示状態（U07・U09・U10）

- テーマは **Expressive Utility v0.3**。Navy Shell（基準 `#253A70`）、白系本文、ニュートラル境界、控えめなキーキャップの影、ブルーの率バー。Figmaの正式ノード・Variablesを優先して値を実装に写す。旧緑色UIへ戻さない。
- 32pxの独自タイトルバー、左の48pxナビ、固定ページヘッダー、**本文だけ縦スクロール**。ウィンドウの最小化・最大化／復元・閉じるが動作する。
- サイズ：初期 **1120×700px**、最小 **800×600px**。ユーザーがリサイズ可能。再起動後も**ウィンドウのサイズ・位置を保持**する。
- 横幅の適応：800〜919pxはコンパクト（行2段／KPI縦）、920〜1119pxは中間、1120〜1359pxは標準、1360px以上は幅を制限した中央配置。各幅の間は余白・列幅を柔軟に調整する。高DPI・文字拡大・画面構成変更を実機検証する。
- 行ハイライトは**ホバー中のみ**（淡い背景＋左端の細いアクセント線）。反応は控えめ（原則150〜200ms）。常時強調・キー操作成功演出・習得済み変更の特別な演出はしない。
- **表示だけの状態は再起動時リセット**：起動時はショートカット一覧、4グループは全展開、期間は7日、対象は「学習中・習得済み」、並び替えは「キー率が低い順」。アプリ起動中の画面切り替えでは選択状態を保持する。
- 既存のライフサイクルを維持：最初の起動時は一覧を表示、最小化はタスクバー、×はウィンドウを隠してバックグラウンド計測継続、トレイのダブルクリックで表示、トレイ「終了」で完全終了。通知クリックで**既存ウィンドウを復元して前面化**。
- 通知の一時停止・再開と計測の全停止・再開は、**トレイと画面右上の「…」メニュー**。全記録の削除は「…」メニュー内（確認ダイアログ必須）。エラーと保存再試行は画面内に表示する。「…」メニューは正式Figmaに反映済み。画面内エラー・保存再試行もデータ状態ページの正式サンプルに追加済み（2026-10-17）。設定用の第3画面は作らない。

## 4. 学習状態と移行（U04・U08・U09）

- 各操作の状態は **学習中／習得済み／対象外**。ユーザーがいつでも変更でき、再起動後も保持する。自動習得判定は行わない。
- **既存設定の移行**：通知ON → 学習中、通知OFF（既存 `muted`）→ 対象外、新規操作・設定のない操作 → 学習中。「習得済み」はユーザーが明示選択したときのみ。
- Figmaのサンプル件数 8/4/2 は初期値ではない。ヘッダーの状態別件数は実際の14操作の状態から計算する。
- 記録画面の対象フィルタは **「学習中・習得済み」「学習中のみ」「すべて」** の3つ。**現在の状態**を過去の全記録と前期間の集計にも適用する。状態変更履歴は保存しない。
- 状態の変更で集計対象・キー率・比較結果は再計算されるが、日別の観測回数自体は変えない。
- 従来の日別回数・設定は保持する。保存スキーマの移行、破損データの保全、将来の再移行を考慮するが、方式は技術設計で決定する。

## 5. 集計・記録・保存（U03〜U06）

- キー率 = **キー操作回数 /（キー操作回数 + マウス操作回数）**。分母0は「記録なし」（0%ではない）。分母が正でキー回数0なら **0.0%** と区別する。括弧内はキー回数／総操作回数。
- 一覧のキー率は**直近7日間**。記録画面は**直近7日間／直近30日間**の切替。基準は**利用者のローカル日付、今日を含む暦日**。
- 前期間の比較は同じ日数の**直前の連続期間**。例：2026-10-17の7日表示→10/11〜17、比較→10/4〜10。30日表示→9/18〜10/17、比較→8/19〜9/17。
- **当日途中でも時間補正しない**。現在得られている記録をそのまま集計する。表示中に新しい操作が記録されたらデータに応じて再計算する。
- 全体キー率・キー/マウス回数・キー率の前期間差（**pt**）・各操作の率と内訳・率バー等は正式Figmaの表現に従う。表示桁や厳密な丸め方式はSpecで明文化する。
- **記録は自動削除せず、無期限に保持**。7/30日表示は維持し、将来の「全期間」分析ができるよう日別・操作別集計を保全する。ユーザーによる**全記録の手動削除**機能は維持する。旧バージョンで既に削除された日付は復元できない。
- **利用開始前・観測していない期間と、観測中に操作が0件だった日を区別**する。現行の回数レコードにこの区別はないため、必要な計測範囲の情報を追加する。記録のある日だけを集計し、存在しない日を根拠なく0件として埋めない。
- 新規利用や移行直後など**前期間の記録が比較に必要な範囲で不足**する場合、比較結果は「—」。現在期間は取得できた記録を集計する。前期間に操作が0回の場合、キー率の増減は「—」だが、操作回数の差は計算する。
- **並び替え5種類**：キー率が低い順／マウス操作が多い順／改善が大きい順／キー操作が多い順／操作回数が多い順。同値なら一覧での操作順を維持。率・改善値が計算できない操作はその並び替えの末尾。欠測を0%として先頭に出さない。
- 初回の記録なし・選択期間に記録なし・前期間比較不可など、Figmaの空状態を区別する。比較可能性の具体的な日付・観測範囲判定は技術設計で明記する。

## 6. 通知・停止・フィードバック（U02・U10〜U12）

- **Windows標準トースト**を使い、独自のElectron通知ウィンドウを置き換える。
- 表示内容はショートカット主役。例：**タイトル「Win + ↑」／本文「ウィンドウを最大化」**。表記は操作ごとに対応させる。**通知音なし**、表示時間はWindows標準設定に任せる。クリックすると既存のアプリ窓を復元・前面化する。
- 学習中のマウス操作で、操作の検出と案内キーの同等性が確認できたら、**操作のたびに個別の通知発行を要求**する。同一操作の連続にも**全体10秒／同一操作60秒等の間引きを設けない**。アプリ側で履歴統合・上書き・独自通知履歴を作らない。
- 全画面表示を理由とした**アプリ側の通知抑制はしない**。OSの集中モード・通知オフ等によりポップアップが表示されない場合はWindowsの判断。**アプリが毎回発行すること**と**OSが毎回表示すること**を同一視しない。
- 通知を一時停止：観測・記録は継続、通知は発行しない。計測を全停止：観測・記録・通知を停止。**習得済み／対象外は記録継続・通知なし**。ショートカットキーによる操作も通知しない。
- 既存の入力重複除外・誤検出防止・同等キーがない場合の無通知は保持する。短時間の保存遅延・期限切れ・通信失敗時に「毎回発行」とどう両立するかは技術設計と試験で明らかにする。
- 通知ID・Windowsアプリ識別・インストール状態でのアクティベーション・OS側で抑制された場合の扱いは技術設計で検証する。音やクリック動作を勝手に変更しない。

## 7. アプリ名・既存データ（U13）

- ユーザーに見える名称を**Shortcut Expert**へ統一。画面、タイトル、トレイ、通知、実行ファイル、インストーラーが対象。
- 既存の観測記録と設定は**維持・移行**する。内部`appId`やWindows通知識別、`userData`・配布形態変更に伴うデータ移行はCodexが技術検証して選定する。安易な名前変更で新しい保存先に切り替わり、過去データが見えなくなることを防ぐ。
- 公開先・署名・OSSライセンス等は本UI刷新の合意だけで新たに決定しない。
