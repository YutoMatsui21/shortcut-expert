# 設定パネル・計測制御

**責務**：通知の一時停止、計測の停止・再開、全記録削除への入口を提供し、トレイと画面の状態を矛盾なく同期する。表示要件は[製品要件](../ui-requirements.md)、[Figmaの設定パネル](https://www.figma.com/design/mMfK6fQQzfhUqRHR7jsGne?node-id=349-2456)を参照。

## 1. UIと操作

- 共通タイトルバーの歯車から`SettingsPopover`（幅330px・最小高さ330px、必要時はパネル内スクロール）を開く。通知・計測・「Windowsへのサインイン時に起動」の3スイッチと削除入口を配置し、本文スクロールと独立させる。
- Enter／Spaceで操作可能。開いたときは**最初の有効な設定スイッチ**へfocusし、すべて無効なら歯車に留める。スイッチの処理中無効化でfocusが本文へ失われた場合は、完了後に元の有効なスイッチへ戻す。他の操作先に移ったfocusは奪わず、削除ボタンへ自動focusしない。
- Esc・外側クリック・歯車再クリック・画面切替・窓非表示／blurで閉じ、必要な場合はfocusを歯車へ戻す。一度設定したfocusを後続snapshotで奪わない。
- 削除入口はパネルを閉じて確認ダイアログへ引き継ぐ。実際の削除・単回確認tokenはMainの[保存・削除契約](../storage/history-deletion.md)で扱う。

## 2. 状態と保存・競合

| 操作 | 期待する状態 |
| --- | --- |
| 通知一時停止 | 計測・保存は継続、通知だけ停止 |
| 計測全停止 | 観測・保存対象の新規採用・通知を停止。停止設定をSQLiteへ保存し、通知希望値は保持 |
| 計測再開 | 保留保存・エラーがない場合だけ新しい観測世代で再開 |
| 再起動 | 通知pauseは解除する。計測は保存した停止／再開状態に従う。旧設定で状態がない場合は計測開始を許可 |
| サインイン時に起動 | 初期OFF。ONならWindowsへ専用引数付きのログイン項目を登録し、サインイン時は画面を出さずトレイへ常駐。画面表示と計測許可は独立 |

- Rendererとトレイは**同じMain command／SerialQueue**を利用する。通知の実効状態は「計測中かつ通知pauseなし」。全停止中は通知スイッチをdisabledにするが希望値を破棄しない。
- 保存失敗・時計異常・helper故障による安全停止をUI操作で勝手に解除しない。停止前に受理した記録の保存は保全し、保存待ちや失敗時の再開は拒否する。旧世代候補と遅延した通知を採用しない。
- 計測設定は保存確定後に反映し、停止は保存前から直ちに有効。保存失敗は既存の設定保存エラー・再試行で扱い、自動再開しない。終了前に保存できなかった設定は再起動後の保持を保証しない。
- 自動起動はインストール済みWindows版で設定可能。登録は利用者の明示操作時のみ変更し、起動／focus時はElectronのログイン項目APIから取得する。Windowsで無効化された項目を再有効化せず、拒否・取得失敗は設定内に表示する。自動起動のエラーだけを理由に計測を停止しない。
- 実アンインストールでアプリ専用Run／StartupApproved項目を削除し、アップデート時は保持する。自動起動設定はSQLiteへ複製しない。
- `CoachWindow`が非永続の`stateVersion`を配信し、`useCoach`は古いsnapshot／IPC応答を無視する。**画面のstateVersionと保存のrevisionは別**であり、遅い応答からトレイ状態を巻き戻さない。

## 3. 検証と限界

- `tests/settings-state.test.ts`：古いIPC応答・トレイcommandとの競合。`tests/learning-state.test.ts`：保存保留・停止／再開・世代と通知。
- 隔離`node scripts/test/smoke.mjs --settings`（配布版は`--packaged --settings`）：2ページ×4幅、focusと閉じ方、スイッチ状態、保存中の禁止操作、トレイcallbackとの同期を確認する。
- `tests/login-startup.test.ts`・`tests/durable-storage.test.ts`と`--activation` smoke：登録拒否／OS無効化、停止保存失敗・再試行、再起動後の停止、非表示起動・手動復元を確認。ログイン項目APIはfixtureへ差し替え、実Windows登録には触れない。
- **NSIS版で別途必要**：ON／OFF後の再サインイン、Windows側無効化、停止／再開の保持、既存インスタンスの手動表示、更新とアンインストール時の登録処理。[#138](https://github.com/YutoMatsui21/shortcut-expert/issues/138)で受入を追跡する。
- **実機で別途必要**：OSトレイのクリック配送、DPI／文字拡大、実入力認識と標準通知。fixture結果はそれらの合格証拠ではない。
