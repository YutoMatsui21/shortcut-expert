## 作業手順と実装の事実

- **共通指示・安全上の不変条件**：[AGENTS.md](../AGENTS.md)。
- **実装・テストの進め方**：[テスト設計Skill](../.agents/skills/test-shortcut-coach/SKILL.md)。関連する変更のときだけ参照する。
- **Issue・PR・CI・mergeの手順**：[GitHub操作Skill](../.agents/skills/github-workflow/SKILL.md)。GitHub操作時だけ参照する。
- **実際のコード構造・動作**：`src/`・`native-helper/`を調査する。文書の実装経路が古い可能性があれば現行コードを確認する。
- **自動テストと技術検証**：`tests/`・`validation/probes/`。実測原本は`validation/evidence/`。人工fixtureの成功を実際のWindows入力の成立証拠にしない。
- **進捗・未解決事項・受入結果**：[GitHub Issues](https://github.com/YutoMatsui21/shortcut-expert/issues)・PR・対応する証拠を参照する。最新の状態を履歴資料から推測しない。

## 判断理由や過去の失敗を調べる場合

現行の仕様・設計を先に確認したうえで、**なぜその方式にしたか、何を試して失敗したか**が必要なときだけ[技術調査・判断根拠](research/README.md)を参照する。

[過去資料](archive/README.md)は、旧MVP・旧実装・実施当時の調査と振り返り。**現行の正本ではない**。現在の判断へ採用するには、改めて要件・コード・Issueとの整合を確認する。

## 文書を更新するときの最小ルール

**変更された情報の正本だけを更新**する。タスクに無関係な資料を読んだり、同じ内容を複数箇所に複製したりしない。

| 変更の種類                          | 更新・確認する対象                                                                              |
| ----------------------------------- | ----------------------------------------------------------------------------------------------- |
| 目的・成功指標・プロダクトの方針    | [product.md](product.md)。機能の合格条件は製品要件に置く                                        |
| MVP・機能・画面の期待動作、受入条件 | [ui-requirements.md](ui-requirements.md)を更新し、影響する個別設計・テスト・Figmaとの整合を確認 |
| 責務・依存関係・検出方式・保存方式  | [design.md](design.md)と影響する`operations/`・`features/`・`storage/`だけ更新                  |
| 実装の詳細のみの変更                | コード・テストを正本とし、仕様や設計意図が変わらなければ文書更新は不要                          |
| 技術調査・未解決事項・一時的な判断  | Issue・PRへ記録。後の判断に再利用する失敗理由・代替案だけ必要に応じて`research/`へ              |
| ファイルの移動・改名                | 移動先と、旧パスを指す参照元のリンクを修正。索引の案内も必要な場合のみ更新                      |

**変更完了前の確認**

1. 変更対象の**正本・関連する設計・テスト**の矛盾がないか、影響範囲だけ確認する。未確定事項を決定済みとして書かない。
2. Markdownを変更したら、追加・編集したリンクの到達先を確認する。**移動・改名時は参照元と移動先内の相対リンクも確認**する。
3. 文書のみの変更ではリンク・記述の整合を検証し、製品の動作を変えない限りビルドや実機テストを追加しない。CIの要否・必須チェックは[GitHub操作Skill](../.agents/skills/github-workflow/SKILL.md)と[開発ガイド](development.md)に従う。

旧仕様・実装履歴・日時付きの検証は現行の正本へ混入させず、必要な経緯だけ[archive/](archive/README.md)から参照する。
