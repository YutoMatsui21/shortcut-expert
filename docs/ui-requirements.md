# Shortcut Expert 製品要件・受入条件

**目的：何を実現し、何をもって合格とするかを決める唯一の製品要件書。** 実装方法は[設計](design.md)、検証コマンドは[開発ガイド](development.md)、進捗と技術的な未解決事項はIssue・PRで管理する。過去の改訂過程や実装件数は本書の要件と混同しない。

## 1. 適用範囲と参照先

- 対象：Windows 11向けデスクトップアプリ。**初回公開は8操作すべての完全対応が必須**。一部だけの公開は承認なしに行わない。
- 外観・文言・レイアウトの基準：[Figma ショートカット一覧](https://www.figma.com/design/mMfK6fQQzfhUqRHR7jsGne?node-id=275-6498)、[記録](https://www.figma.com/design/mMfK6fQQzfhUqRHR7jsGne?node-id=275-6552)、正式テーマ Expressive Utility v0.3。Figmaのサンプル件数・旧操作構成は仕様ではない。
- 本文が機能・例外・受入条件の正本。旧MVPや過去の工程記録は[archive/](archive/)を参照する。**Figmaの見た目や隔離テストの成功を、実入力の対応完了とは見なさない。**
- 既存の安全契約（重複除外、入力由来／対象／結果の照合、保存失敗の保全、時計後退時の保全、限定IPC、Electronのsandbox/contextIsolation、トレイ常駐）を維持する。

## 2. 初回対象の8操作

| ID | 操作 | 対象マウス入力 | 同等なキー入力・計測単位 |
| --- | --- | --- | --- |
| W12 | タスクバーのアプリを開く | タスクバーの**アプリアイコン**をクリック | 存在する主タスクバー1〜10番の`Win+1〜9/0`。起動・前面変更をW01へ重複計上しない |
| W01 | ウィンドウを切り替える | 背後の**別の通常窓**を直接クリックし前面化 | `Alt+Tab`で別窓へ確定。Alt保持中にTabを複数回押しても最終切替1件 |
| W03 | ウィンドウを最大化する | 最大化ボタン、タイトルバーダブルクリック、**画面上端への直接ドラッグ**＋最大化結果 | `Win+↑`と結果の一致。画面跨ぎでW02が成立すれば両方記録 |
| W04 | 最大化解除・最小化 | 復元ボタン・タイトルバーダブルクリック、または最小化ボタン＋結果 | `Win+↓`。同一窓への短い連続押下は1操作。最大化中の最小化は繰り返しが必要な場合がある |
| W06 | 左右半分に配置する | 左右端への直接ドラッグ＋半分配置 | `Win+←/→`と半分配置 |
| W07 | 画面の四隅に配置する | 四隅への直接ドラッグ＋四分割配置 | Win保持中の方向キー列を最終確定で1件。途中のW06を重複計上しない |
| W02 | 別画面に移動する | タイトルバードラッグの始終で**同一窓のモニターが異なる**ことを確認 | `Win+Shift+←/→`と移動結果。方向が同等と確証できるときだけキー案内 |
| W11 | ウィンドウを閉じる | 閉じるボタンと対象窓の破棄 | `Alt+F4`と対象窓の破棄。非表示・トレイ格納は除外 |

**共通判定**：入力由来、同一対象、操作結果、キーの同等性を照合する。操作成立だけ確証でき、案内キーが不明なら**記録のみ**。成立自体が不明なら**記録も通知もしない**。どちらも初回リリースの「完全対応」とは扱わない。

<a id="w01-w12"></a>
### W01・W12の境界

- タスクバーアプリアイコンのクリック／有効な`Win+数字`は**W12だけ**。W01はそれ以外の通常窓の直接クリック／`Alt+Tab`だけを扱う。
- W01は切替前後の対象と最終確定を確認する。`Esc`取消、同じ窓への復帰、入力と結び付かない前景変更は除外。Edge等の**タブ操作**、Task Viewや検索起動は初回対象外。
- W12は存在するタスクバー項目への**入力の成立**を確認する。アプリの起動・復帰・個別窓の選択結果までは要件にしない。存在しない番号、修飾キー追加、注入、リピートは除外。番号・並び・主／副タスクバーの情報が不確かなら誤って記録／案内しない。
- 初回はW12の`Win+数字`1候補、W01の`Alt+Tab`1候補だけを案内する。起動状態に応じた別候補、11番目以降、**1操作への複数代替キー**は将来の[#96](https://github.com/YutoMatsui21/shortcut-expert/issues/96)で扱い、初回受入を妨げない。

<a id="compound-gesture"></a>
### 複合ドラッグ（W02＋W03／W07）

- **1回のドラッグ**が別モニターで終了し、同じ終端で最大化または四隅配置も確定した場合は、**W02とW03／W07を各1件**記録する。通常位置への移動ならW02だけ、同じモニター内の配置ならW03／W07だけ。元モニターへ戻して終了した場合のW02は0件。
- 途中の派生復元W04や四隅到達前の中間W06は増やさない。同じ操作IDの再送／重複も増やさない。開始・終了の同一対象、入力経路、モニター、最終状態を結び付け、状態スナップショットだけで因果を推測しない。
- 異なる操作IDの**2件を原子的に保存**し、ACK喪失後の再送でも二重計上しない。キーが確証された学習中の操作だけ、**1つのWindows通知に別々の行**で表示する。各キーが複合動作を単独で再現するとは表現しない。W02の方向不明時も、W03／W07の案内は独立して判断する。
- 画面跨ぎ半分配置（W02＋W06）は今回の対応確定対象に含めない。実装・検証の追跡は[#113](https://github.com/YutoMatsui21/shortcut-expert/issues/113)。#96の「1操作に複数の代替キー」とは別要件。

<a id="excluded-operations"></a>
### 初回対象外と既存データの扱い

W05（旧最大化解除）はW04に統合。W08（Snap Layout呼び出し）・W10（Task View）・W09（デスクトップ表示）・W14（全最小化）・W13（上下半分配置）は初回の一覧・記録・通知・関連候補・受入に含めない。Snap Layout選択UIを通る配置もW03/W06/W07へ帰属させない。旧W08の観測実装は通常の8操作経路で採用・通知しない。過去の検証は[W08の過去設計](archive/design/snap-invocation.md)と[research/](research/)に残す。

8操作への切替に伴う**旧データ削除は承認済み**で、W04/W05間の履歴・学習状態の統合を要求しない。ただし、以後の通常のデータ保全・移行契約まで撤回した意味ではない。

## 3. UI・画面動作

### 画面構成とデザイン

- **「ショートカット一覧」「記録」の2画面**。一覧は4グループ（折り畳み可）、対象は8操作。設定専用の第3画面は設けない。
- Navy Shell（基準`#253A70`）・白系本文・控えめなキーキャップ影・青の率バーなど、Figmaの正式ノード／Variablesに合わせる。旧緑色UIは使用しない。
- 32pxのタイトルバー、48pxの左ナビ、固定ページヘッダー、**本文だけスクロール**。最小化・最大化／復元・閉じるの操作を提供する。
- 初期サイズ`1120×700px`、最小`800×600px`。リサイズと位置・サイズの保存に対応。幅`800–919 / 920–1119 / 1120–1359 / 1360px以上`の4段階で適応し、DPI／文字拡大／画面構成変更も検証する。
- ホバー行だけ淡く強調し、操作成功アニメ・常時強調は不要。画面内容の文言・余白・率表示はFigmaに従う。

### 表示状態・常駐・設定

- 起動時は一覧、4グループ全展開、期間7日、対象「学習中・習得済み」、ソート「キー率が低い順」。これら**画面表示だけの選択は再起動でリセット**し、起動中の画面切替では保持する。
- 初回・2回目以降とも、スタートメニューや実行ファイルからの手動cold起動では一覧を表示。非表示中の再起動要求は既存窓を復元・前面化し、二重観測を作らない。`×`は非表示・計測継続、最小化はタスクバー、トレイのダブルクリックや通知クリックでは**既存の窓**を復元・前面化。トレイ「終了」で完全終了。
- 共通トップバーの歯車（最小化ボタンの左）から**設定ポップオーバー**を開く。通知／計測の2スイッチ、確認付き「すべての記録を削除」を配置。歯車再クリック・外側クリック・`Esc`で閉じる。停止・保存失敗時の状態／再試行を画面に表示し、キーボード操作も保証する。

## 4. 学習状態・集計・保存

### 学習状態

- 各操作は**学習中／習得済み／対象外**。手動で変更し、再起動後も保持。自動習得はしない。どの状態でも操作記録は継続し、**学習中だけ**同等キーを通知する。
- 旧通知ON／設定なし＝学習中、旧通知OFF（`muted`）＝対象外に移行。習得済みは明示的な選択のみ。
- フィルタは**学習中・習得済み／学習中のみ／すべて**。現在の状態を現在期間・前期間双方へ適用し、状態変更履歴は保存しない。操作回数そのものは書き換えない。

### 集計と欠測

- **キー率＝キー回数÷（キー回数＋マウス回数）**。分母0は`—`（記録なし）、分母が正しくキー0なら`0.0%`。内訳はキー回数／全操作回数。
- 一覧は**今日を含む直近7暦日**。記録画面は7／30日を切り替え、直前の同日数の期間と比較する。**途中の当日を時間補正しない**。変化は`pt`で表示し、データ追加時に再計算する。
- **欠測と、観測できた期間の0回を分ける。** 比較期間に部分欠測があっても得られた回数で計算し、ゼロ補完・日数補正はしない。比較付近のinfoに「一部の時間帯で記録を取得できていないため、実際の利用状況と異なる可能性があります。」と説明する（J01）。
- 前期間に比較できる記録／観測根拠がまったくなければ差分は`—`。既知の0回と混同しない。キー率の分母0なら率の増減は`—`。現在期間の欠測にも同じ注意を示す。
- ソートは**キー率が低い順／マウス操作が多い順／改善が大きい順／キー操作が多い順／操作回数が多い順**。同値は操作の表示順、算出不能は末尾。初回・期間記録なし・比較不可の空状態を区別する。
- 記録は**自動削除せず無期限に保持**。利用者による全記録削除を提供し、設定は保持する。生キー・文字・URL・窓タイトル・画像等は保存・送信しない。移行・保存失敗時の原本保全は[保存設計](storage/durable-storage.md)を参照する。

## 5. 通知・停止・障害

- **Windows標準の無音トースト**を使用。単独操作はキーをタイトル、操作名を本文に表示。表示時間・集中モード・通知センター履歴はOSに委ね、アプリの発行要求成功とOSの表示成功を区別する。
- 学習中の**確証済みマウス操作**を保存した後、独立したgestureごとに1通知を要求。全体10秒／同一操作60秒等の独自間引きはしない。複合ジェスチャは**最大1通知（適格な操作を別行で表示）**。全画面を理由にアプリ側では抑制しない。
- 通知一時停止：**観測・記録は継続、通知だけ停止**。計測全停止：観測・記録・通知のすべて停止。習得済み・対象外、キーボードによる操作でも通知しない。
- **保存が成功した後だけ発行**（J02）。保存遅延を旧TTLで破棄せず、発行直前に停止状態と学習状態を再確認する。保存失敗は保留・計測停止・画面エラー・再試行。復旧しても**古い通知を後から一括送信しない**。通知APIの結果不明時も重複を避けるため自動再送しない。
- **通知センターからの起動**（J03）：起動中は既存窓を復元、完全終了後は通常起動して一覧表示・計測開始。二重インスタンス／二重観測は禁止。インストーラー識別・OSのクリック／フォーカス挙動は実機受入で検証する。
- 利用者に見える名称は**Shortcut Expert**へ統一。画面・トレイ・通知・実行ファイル・インストーラーが対象。識別子や保存先の変更で既存データを失わないようにする。

<a id="release-acceptance"></a>
## 6. 初回リリースの合格条件（R01・R02・J04）

**8操作すべてを、同一の候補buildで次の条件に合格させる。未確認の操作が1件でもあれば公開判定はBLOCKED。**

| 条件 | 合格の判断 |
| --- | --- |
| 操作成立（R01） | マウス／キー双方の入力由来・対象・結果・同等性が確証できる |
| 記録と通知（R01） | 正しい日別集計、学習中の適切な通知、停止・学習状態・保存失敗の例外が正しい |
| 誤検出防止（R01/R02） | 取消・類似操作・自動状態変化・連続操作の負例で**誤記録／誤通知0件** |
| 自然入力（R02） | 実際の対象窓・入力・結果・保存・通知を確認。各ケース原則1回、予想外のときだけ原因確認後に再試行 |
| 一般環境（J04） | 一般的なWindows 11・横長ディスプレイ・代表アプリ・日常的なタスクバー条件で成立。自作窓や特殊配置だけの合格は不可 |
| 配布と保全 | 同梱build、OS通知・トレイ、NSIS導入／再導入／削除、既存データの保全を確認 |

実機試験は代表アプリ・起点状態・対応するOS／画面構成・負例を定義し、結果と未確認条件を残す。手動1回の成功は**その条件での機能確認**であり、認識率95%以上や全環境での無条件保証を意味しない。人工fixture・画面への表示・記録のみの成立を完全対応の証拠にしない。

対応条件の実質的な縮小、キーのみ／記録のみへの変更、対象操作の削減、段階リリースは**ユーザーの承認なしに採用しない**。実装済み・未検証・対応困難を分け、未確定の成立条件は該当Issue・検証資料で追跡する。

## 7. 初回に追加しない機能

設定の第3画面、独自通知履歴、通知内ボタン、音・成功アニメ、アカウント／クラウド同期、自動習得、W01/W12の複数代替キー候補は追加しない。技術的な調査・過去のIssue結果は保持するが、**それらを現在の要件と取り違えない**。
